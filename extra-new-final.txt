h2. 1. Overview

- Fetches request (shortJSON) from DB  
- Builds DAJSONDocument (PCSM input)  
- Executes blocks in parallel  
- Calls PCSM (NTJSEMJSONInterface - sp5 jar)  
- Performs post-processing  
- Stores response in DB  
- Returns summarized response  

{info}
Core class: DecisionServiceImpl  
SMPOJO jar → DAJSONDocument and models  
sp5 jar → NTJSEMJSONInterface for PCSM execution  
{info}

----

h2. 2. Controller Layer (DecisionController)

# Validates request type using *DesType.isRequest()*  
# Extracts *productAppId*  
# Starts SLA timer (*StrategicDecisionTime*)  
# Sets MDC context (*productAppId*, *correlationId*)  
# Delegates to *DecisionServiceImpl.callDecisionEngine()*  
# Logs total execution time  

{code:java}
MDC.put(PRODUCT_APP_ID, productAppId);
MDC.put(CORRELATION_ID, correlationId);
{code}

{info}
MDC enables request-level log tracing across parallel execution.  
Controller handles only validation, timing, and delegation.  
{info}

----

{code}

   ↓

      ↓

      ↓

      ↓

{info}

h2. 6. PARAMTER Caching

{code}
Application Startup
   ↓
SdsParameterMapperImpl (@PostConstruct)
   ↓
Fetch data from vec_sdsparam
   ↓
Map to PcsmInitDataBlock
   ↓
Store in memory (cache)

Request Flow
   ↓
SdsParameterTask
   ↓
Reads from PcsmInitDataBlock (based on parameterChangeDateTime)
   ↓
Sets PARAMTER into DAJSONDocument
{code}

{info}
PARAMTER is loaded once at startup and stored in memory.  
During request processing, no DB call is made — data is read from cache using parameterChangeDateTime.  
{info}

----

h2. 7. Parallel Execution

{code}
Create Callable Tasks (20 blocks)
   ↓
executor.invokeAll(tasks, timeout)
   ↓
validateFutureList()
   ↓
Tasks update PcsmRequest
   ↓
DAJSONDocument ready
{code}

{info}
No Future.get() calls.  
No aggregation step.  
Shared PcsmRequest object is updated by all tasks.  
{info}

h2. 12. Exception Handling

{code}
Exception
   ↓
ControllerAdvice
   ↓
StrategicDecisionException
   ↓
storeErrorResponse()
   ↓
Return Error Response
{code}

- DES001 → DB error  
- DES002 → Task failure  
- DES003 → PCSM failure  
- DES004 → JSON error  
- DES100 → Business validation  

{info}
All errors are logged and stored in DB.  
{info}

h2. 15. Adding New Block

|| Step || Change || Risk ||
| 1 | SMPOJO | Model update | Block missing |
| 2 | ApiConstants | Add constant + EXPECTED_TASK_COUNT | DES002 |
| 3 | PcsmConfiguration | Add block | Task not created |
| 4 | CSV | Add mapping | Wrong data |
| 5 | Config | ConfigRecord | Initialization failure |
| 6 | Block | Converter | Mapping failure |
| 7 | Sequence | BodySequence | Block not executed |
| 8 | Mapper | JsonMapper | Missing values |
| 9 | Task | Executor | Block skipped |

{info}
EXPECTED_TASK_COUNT mismatch is the most common production failure.  
{info}
